# Phase 2 isolated procedure fixture plan

Prepared 2026-09-30. The separate database, schemas, stage, tables, view, and copied procedure have been deployed; no procedure fixture has run.

The deployed procedure and its Snowpark modules use fully qualified `QUAKEWATCH.RAW` and `QUAKEWATCH.CURATED` table names. Running a synthetic update or deletion through that procedure would write fixture records into the real project tables. The earlier temporary-table check exercised only the checked-in current-view SELECT, so it cannot establish procedure-level update or tombstone behavior.

Use a separate, clearly named test database with `RAW` and `CURATED` schemas and the same table definitions. Build a **test-only copy** of the procedure bundle and SQL with a checked, exact replacement of the `QUAKEWATCH.` database qualifier; leave the production files unchanged. The test copy must use its own internal stage and procedure. The offline [namespace validator](../scripts/phase2_fixture_namespace.py) enumerates fully qualified object references in every procedure module and required DDL file, rejects unknown databases or schemas, and checks that no source database qualifier survives the rewrite. Run `PYTHONPATH=src:. .venv/bin/python scripts/phase2_fixture_namespace.py`; this does not connect or create a bundle. Recheck the account's supported Python runtime and Snowpark package before deploying the copied procedure.

Build the test-only import ZIP and SQL files with `PYTHONPATH=src:. .venv/bin/python scripts/build_phase2_fixture_bundle.py`. The builder validates every source before writing to ignored `data/procedure/phase2_fixture/`, then inspects the generated ZIP and SQL for production references. This local artifact build does not deploy anything.

The account setup is [phase2_fixture_setup.sql](../sql/phase2_fixture_setup.sql). It creates a new database, `RAW` and `CURATED` schemas, and grants only the existing `QUAKEWATCH_ROLE` the object-creation privileges needed there. It deliberately has no `IF NOT EXISTS`: if the name is already occupied, setup must stop for inspection. The approved runner created the database and schemas on 2026-09-30; the later test stage and tables will be created by the project role in a separate step.

Preview the [name preflight](../scripts/phase2_fixture_name_check.py) with `PYTHONPATH=src:. .venv/bin/python scripts/phase2_fixture_name_check.py`. Its approved `--execute` mode used the existing `quakewatch_admin` profile for one metadata-only `SHOW DATABASES LIKE` query; it filters the result to an exact name because SQL `LIKE` treats underscores as wildcards. It does not create or alter an account object, and it never prints the profile password. On 2026-09-30, this check reported `Fixture database name: available for setup review`. Recheck immediately before creation because availability can change.

The guarded [setup runner](../scripts/phase2_fixture_setup.py) previews the 12 reviewed statements with `PYTHONPATH=src:. .venv/bin/python scripts/phase2_fixture_setup.py`. Its approved `--execute` call rechecked the exact name on the same admin connection immediately before running SQL, rejected edits to the reviewed statement list, and verified database and schema visibility afterward. It returned 12 statements executed. Do not rerun: the name guard will now stop because the database exists. Cloud services usage and storage charges have not been measured.

The [fixture deployment runner](../scripts/phase2_fixture_deploy.py) previews with `PYTHONPATH=src:. .venv/bin/python scripts/phase2_fixture_deploy.py`. Its offline checks require the reviewed test-only ZIP hash and current generated SQL. The approved live run on 2026-09-30 required both fixture schemas to be empty, rechecked Python 3.12 plus pinned Snowpark 1.55.0 in the account package catalog, created the test-only internal stage, uploaded the ZIP, and applied RAW/curated DDL. The terminal reported `stage_upload: UPLOADED` and 16 SQL statements executed. It did not call the procedure or load source fixtures. Its empty-schema guard now prevents rerunning this deployment command. Actual warehouse and storage charges remain unmeasured.

The local [fixture-attempt builder](../scripts/build_phase2_fixture_attempts.py) prepares four ignored, one-row RAW attempts with explicit `fixture_only` markers, synthetic window audits, stable payload hashes, and internally reconciled counts. Run `PYTHONPATH=src:. .venv/bin/python scripts/build_phase2_fixture_attempts.py`; this makes no USGS or Snowflake request. Its count fields refer to local fixture rows, not live source counts or coverage. Load these attempts into **test RAW only** after a separately approved guarded loader is ready. Process original, later revision, and tombstone in that order, then replay the original as a fourth attempt. After each call, check the revision fact, current view, processing audit, and duplicate grain keys. Expected current state: original active, later magnitude `1.28`, absent after deletion, still absent after stale replay. Preserve all historical revision rows and report rejects. A further same-attempt rerun should merge zero new revisions; the stale replay itself may update the existing old revision's fetch time without creating a new logical revision.

The [fixture RAW loader](../scripts/phase2_fixture_raw_load.py) previews with `PYTHONPATH=src:. .venv/bin/python scripts/phase2_fixture_raw_load.py`. It checks the four exact local source features/hashes, then stops without connecting. Its approved `--execute` run on 2026-09-30 required empty test RAW tables and empty per-attempt stage paths, then PUT/COPY loaded each one-row fixture, reconciled the COPY and attempt-filtered RAW count, and appended a synthetic complete receipt. The terminal returned `loaded_rows: 1` for each of the four attempt IDs. It targeted only `QUAKEWATCH_PHASE2_FIXTURE.RAW`. The empty-table guard now prevents rerunning this loader. No fixture procedure call has run yet.

This test database and its staged files would persist until deliberately cleaned up. Creating it, loading it, running the warehouse, and later deleting it each require a separate review of cost and data effects. No command in this plan authorizes those actions. The plan does not change the frozen core architecture: production still reads USGS batch data through the existing RAW and Snowpark path. This fixture proves model behavior on synthetic inputs only, not that the catalog-wide update sweep captured every real old-event change.
